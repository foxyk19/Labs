## Принятые правила

- Слова: нижний регистр, разбиение по пробельным символам, удаление `.,!?;:` с краёв, пустые результаты пропускаются.
- Темы: уже в нижнем регистре, сравнение точное; результат — отсортированный список без повторов.
- Записи: ключи — строки, `amount` — неотрицательное целое, входные списки и словари не изменяются.
- Неизвестная категория даёт `[]`, пустой список записей даёт `{}`.

## Ответы на вопросы для защиты

- **Выбор структуры.**
  - Частоты слов: `dict`, потому что нужно соответствие «слово → количество» с быстрым поиском по слову.
  - Темы: `set`, потому что нужны уникальные значения и операции пересечения (`&`) и объединения (`|`).
  - Запись занятия: `dict`, потому что у полей есть имена (`title`, `hours`, `completed`) и порядок полей не важен.
  - Пара: `tuple`, потому что это неизменяемая пара фиксированного размера, её удобно распаковывать в две переменные.
- **Почему запись удобно представить словарём.** Поля читаются по смыслу (`record["hours"]`), а не по номеру позиции; можно добавить новое поле (`completed`), не ломая остальные; видно, что означает каждое значение.
- **Поведение `.get()`.** `record.get("hours", 0)` возвращает значение по ключу, а если ключа нет, возвращает запасное значение (`0`) и не вызывает ошибку. Поэтому `counts[word] = counts.get(word, 0) + 1` работает и для нового слова. Запись `record["hours"]` для отсутствующего ключа вызвала бы ошибку `KeyError`.
- **Почему множество сортируют перед выводом.** У множества нет индексов и гарантированного порядка вывода. `sorted(values)` даёт воспроизводимый список, который можно сравнивать в тестах и получать при каждом запуске одинаковым.
