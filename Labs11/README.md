# Лабораторная работа 11. JSON и получение данных по HTTP

**Вариант:** 14 — незавершённые задачи пользователя с длиной названия не меньше порога.
**Python:** 3.10+ (проверено на 3.13). Внешние библиотеки не нужны.

## Файлы

| Файл | Назначение |
|---|---|
| `todos.json` | Учебный набор (точное содержимое из задания) |
| `analysis.py` | `validate_todos`, `completion_counts`, `top_users`, `leader_tasks`, `select_tasks`, `load_todos`, `dump_json` |
| `main.py` | Чтение, проверка, сводка, ввод `user_id` и порога, сохранение результатов |
| `leaders.json` | Завершённые задачи лидеров: id `[1, 3, 4, 5]` |
| `selected.json` | Результат варианта 14 (для `user_id=5`, порог 5: id `[2]`) |
| `test_analysis.py` | Автоматические проверки |
| `fetch_profile.py` | HTTP-упражнение (профиль GitHub по логину) |
| `profile_sample.json`, `read_sample.py` | Офлайн-режим упражнения |

## Запуск

```
python main.py
python test_analysis.py
python fetch_profile.py      # нужен интернет
python read_sample.py        # без интернета
```

## Что делает `main.py`

1. Читает и проверяет `todos.json`.
2. Выводит число выполненных задач по пользователям и лидеров (`{5: 2, 10: 2}`, лидеры `[5, 10]`).
3. Запрашивает положительный `user_id` и порог длины названия (целое >= 0), повторяя ввод при ошибке.
4. Только после успешной обработки записывает `leaders.json` и `selected.json`; при ошибке входа прежние результаты не трогаются.

Обработчики: `FileNotFoundError`, `UnicodeError`, `json.JSONDecodeError`, `ValueError`, `OSError`. `UnicodeError` и `JSONDecodeError` — подклассы `ValueError`, поэтому стоят раньше общего `ValueError`.

## Проверки

`test_analysis.py` покрывает: учебный набор; пустой список и набор без выполненных; один и несколько лидеров; вариант 14 (пример из таблицы, граница порога 5/6, неизвестный пользователь, пользователь без незавершённых, порядок, неверный порог, неизменность исходных записей); ошибки структуры (объект вместо списка, повторный `id`, нет `userId`, `completed="false"`, `id=true`); запись и повторное чтение JSON; неверный JSON и кодировку. Сетевых вызовов при импорте нет.

Вариант 14 не использует текстовый параметр, поэтому проверки смешанного регистра не требуются.

## HTTP-упражнение

- **Адрес** `https://api.github.com/users/<логин>` — ресурс «профиль пользователя»; логин кодируется через `quote`.
- **GET** — метод чтения ресурса, данные на сервере не меняются.
- **Таймаут 10 секунд** — чтобы программа не зависала при отсутствии ответа.
- **Обработчики:** `HTTPError` — сервер ответил кодом ошибки (404, 403, 429); `URLError`/`TimeoutError` — нет сети или ответа; `ValueError`/`UnicodeError` — неверные данные; `OSError` — ошибка записи `profile.json`.

**Результат запуска:** запрос для `octocat` из среды, в которой выполнялась работа, вернул `HTTP 403`, поэтому профиль получен не был. Использован равноценный офлайн-режим: `profile_sample.json` (`{"login": "demo", "id": 1, "name": null}`) читается через `json.load`, выводится логин `demo`. Это учебные локальные данные; `null` в поле `name` не заменяется выдуманным значением. Если у вас есть интернет, запустите `python fetch_profile.py` и введите `octocat`.
