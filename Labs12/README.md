## Назначение

Консольная программа для ведения списка мероприятий: просмотр, добавление, поиск, смена статуса, удаление, статистика, сохранение в JSON.

## Запуск

```
python main.py                 # использует data.json из папки проекта
python main.py другой.json     # необязательный путь к файлу данных
python test_logic.py
python test_storage.py
```

Абсолютные пути в коде не используются: папка проекта определяется через `Path(__file__)`.

## Структура

| Файл | Ответственность |
|---|---|
| `logic.py` | `validate_records`, `add_record`, `find_records`, `set_completed`, `delete_record`, `statistics` (без ввода/вывода и файлов) |
| `storage.py` | `load_records`, `save_records` (JSON, UTF-8; запись через временный файл) |
| `main.py` | Меню, ввод, сообщения |
| `test_logic.py`, `test_storage.py` | Автоматические проверки (файлы — во временной папке) |
| `data.json` | Вымышленный набор из 4 мероприятий |

Контракты (подробно — в строках документации): `add_record`, `set_completed`, `delete_record` изменяют переданный список; `set_completed` и `delete_record` возвращают `True` при успехе и `False` для неизвестного ID; `find_records`, `statistics`, `validate_records` данные не меняют. Глобального состояния нет.

## Формат данных

```json
{"id": 1, "title": "Хакатон по Python", "category": "конференции", "amount": 40, "completed": false}
```

- `id` — положительное целое, уникальное; новый id = максимальный + 1 (для пустого списка 1), после удаления id не перенумеровываются.
- `title`, `category` — непустые строки; при добавлении пробелы по краям убираются.
- `amount` — целое >= 0 (не `bool`); `completed` — строго `bool`.
- Корень — список объектов; все пять ключей обязательны, дополнительные ключи допустимы.

## Набор данных и ожидаемая статистика (посчитана вручную)

Всего 4; проведено 2 (id 2, 3); не проведено 2 (id 1, 4); сумма участников 40 + 25 + 15 + 20 = 100; по категориям: встречи 45, конференции 55.

## Результаты сценариев приёмки

Автоматически проверено в `test_logic.py` / `test_storage.py`, остальное — вручную запуском `main.py` со скриптованным вводом.

| Сценарий | Результат |
|---|---|
| Файла нет | Сообщение, пустой список, меню доступно — ОК |
| JSON `[]` | Все значения статистики 0 — ОК (тест) |
| Записи с количеством 4 и 2, вторая завершена | Всего 2, проведено 1, не проведено 1, сумма 6 — ОК (тест) |
| Название `  Python  ` | Сохранено `Python` — ОК (тест) |
| Поиск `PY` при названии `Python` | Найдено — ОК (тест и вручную) |
| Пустое название, `-1`, `abc` | Повторный ввод, лишней записи нет — ОК (вручную) |
| Смена статуса неизвестного ID | Сообщение, данные не изменены — ОК |
| Удаление отменено | Запись сохранена — ОК |
| Удалена запись 1 из списка с ID 1 и 2 | Остаётся ID 2, следующая новая получает ID 3 — ОК (тест) |
| Сохранение и перезапуск | Все поля и статусы восстановлены — ОК |
| Повреждённый JSON, повторный ID, не UTF-8 | Запуск прекращён с причиной, файл не изменён — ОК |
| Ошибка сохранения | Сообщения об успехе нет, программа остаётся в меню — ОК |

Дополнительно проверено: неизвестная команда меню (сообщение и повтор меню); при выходе ответ, отличный от «да»/«нет», повторяет вопрос; пустой поисковый запрос отклоняется.

## Путь одной записи (для защиты)

Ввод в `main.py` (`cmd_add`) -> `add_record` (проверка, `strip`, новый id, `completed=False`) -> список в памяти -> `save_records` (JSON во временный файл, затем замена `data.json`) -> при следующем запуске `load_records` -> `validate_records` -> тот же список в памяти.
